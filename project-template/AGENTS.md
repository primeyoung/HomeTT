## 项目规则

1. 开始任务前阅读本文件、README 和相关 `docs/`。
2. 遵循当前仓库结构和现有技术栈；未经确认不随意换框架或升级主版本。
3. 修改前检查 Git 状态，保护用户已有修改。
4. 新功能必须明确验收标准，并补充适当测试。
5. Bug 修复必须尽量增加回归测试。
6. API、数据库结构、权限、业务流程变化时同步更新文档。
7. 不提交密钥、令牌、真实用户数据或本地环境文件。
8. 不通过删除/跳过测试或弱化检查来制造成功。
9. 生产部署、破坏性迁移、真实数据修改和远程发布必须先审批。
10. 完成时说明变更、测试证据、未解决问题和运行方式。
